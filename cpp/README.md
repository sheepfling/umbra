# Native C++ implementation

This directory owns Umbra's C++20 implementation and its native test suite.
The official IEEE 1516.1-2025 headers are intentionally vendored under
[third_party/](../third_party/README.md), not recreated here.

## Layout

| Path | Purpose |
| --- | --- |
| include/umbra/ | Umbra-owned public helper headers. |
| src/ | Definitions for the standard-facing binding and value types. |
| src/internal/handles/ | Private handle values, directories, and handle encodings. |
| src/internal/fom/ | FOM catalog, validation, composition, and libxml2 adapters. |
| src/internal/federation/ | Federation lifecycle, registry, transport, and management coordination. |
| src/internal/time/ | Time state, bounds, scheduling, and time-selection support. |
| src/internal/callbacks/ | Callback dispatcher and callback-session state. |
| src/internal/observability/ | Runtime instrumentation, service reports, and MOM report encoding. |
| src/internal/runtime/ | Cross-cutting ambassador, authorization, and UTF-8 helpers. |
| generated/ | Checked-in fallback ambassador shell generated by a tool; do not edit by hand. |
| tests/ | Native Catch2 tests and smoke tests. |
| tests/data/ | XML fixtures used by FOM, region, and model-composition tests. |

The [private runtime map](src/internal/README.md) explains the domain
boundaries, dependency direction, and file-placement rules for src/internal/.
The [native test guide](tests/README.md) explains test layers, fixture
placement, and the smallest useful test loop.

The root CMake file owns targets and test registration. The principal installed
targets are umbra::rti, umbra::fedtime, and umbra::authorizer. See the root
README for the ordinary build and [cmake/](../cmake/README.md) for the
installed-package smoke path.

## Working on a native capability

1. Confirm the boundary in [architecture](../docs/architecture/ARCHITECTURE.md)
   and the relevant focused design record.
2. Add private state under src/internal only when it is not part of Umbra's
   public helper surface.
3. Add or update a focused test in tests and a fixture in tests/data when a
   model input is needed.
4. Use the native test lanes in
   [requirements and testing](../docs/testing/REQUIREMENTS-AND-TESTING.md).

## Generated fallback

generated/rti_ambassador_shell.hpp is produced by
tools/generate_rti_ambassador_shell.py from the pinned IEEE header inventory.
Regenerate it rather than hand-editing it, then review the resulting diff with
the corresponding inventory update.
