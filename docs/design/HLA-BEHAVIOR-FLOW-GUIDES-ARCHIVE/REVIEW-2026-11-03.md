## 2025 joined-federate HLAfederateState after failed or aborted Restore — 2026-11-03

**Question:** When a 2025 Restore ends unsuccessfully, how does the live
`HLAfederateState` value relate to `federationNotRestored` callback delivery
and observer reflections?

**Evidence:** Member-reported failure, explicit abort, and a preparation or
application exception caught while the restore operation remains active each
plan failed completion notifications and clear the restore operation. A fresh read from the live
encoder then derives `ActiveFederate` (`1`). Embedded failure delivery invokes
`federationNotRestored` without queuing a conditional state update. The
configured-process service turns the same notification records into per-member
Push or queued private `ReceiveInteraction` events, and the callback bridge invokes
`federationNotRestored`; that event carries no member-state update. The 2025
MIM names successful Restore milestones, not `Federation Not Restored`, as
conditional update triggers. The configured-process failure and abort tests
assert callback reason/order, not a member-state value or reflection.

The broad application catch also attempts `RTI_UNABLE_TO_RESTORE`, but it spans
state application and later callback-work rebinding. The restore helper clears
the operation before those route checks. If a post-apply route check throws,
the catch's shared notification builder finds no active operation to enumerate.
This is a source-observed, untested control-flow edge; it is not a claimed
externally observed outcome or conformance defect.

**Disposition:** Added a 2025-only failure-state flow to the
[joined-federate MOM lifecycle guide](../HLA-2025-JOINED-FEDERATE-MOM-OBJECT-LIFECYCLE-FLOW-GUIDE.md#failed-or-aborted-restore-callbacks-and-the-live-state).
It keeps the live projection, automatic conditional update, and embedded or
process callback-delivery path distinct. No source or test changes were made.

**Visual review:** Mermaid CLI 12.0.0 rendered the flowchart and local
screenshot review found it readable. It is one additional selected chart; the
queue is now 88 reviewed / 0 pending. GitHub rendering and whole-tree visual
quality remain unverified.

**Link check:** The new guide subsection's 18 implementation/MIM line anchors
and two focused-test line anchors resolve; this review's guide-heading link
also resolves. These 21 destinations are not folded into the historical
aggregate.

**Follow-up:** Trace the post-apply Restore route-rebinding checks and their
membership/callback-route invariants to determine whether a thrown check can
reach the failure catch after `restoreOperation` has been cleared. Keep the
result source-bounded; hand it to an implementation owner if reachability
cannot be ruled out. No builds or tests for this documentation review.

[encoder](../../../cpp/src/internal/federation/federation_registry_mom_object_state.cpp#L710)).

requesting member and resolves known RTI-owned MOM objects through the

([public adapter](../../../cpp/src/internal/runtime/umbra_rti_ambassador_request_attribute_value_updates.cpp#L23),

entitlement. The service packages the returned values into a direct RTI-owned
attribute event, not a provider `provideAttributeValueUpdate` request.

`reflectAttributeValues`; source therefore predicts a request-time value of `1`

The focused embedded state test requests values during its successful Save/
Restore flow, while no configured-process test asserts a request or reflection
of `HLAfederateState` after failed Save
([embedded request case](../../../cpp/tests/joined_federate_mom_federate_state_save_restore_catch2.cpp#L297)).

## 2025 configured-process HLAfederateState Save callback route — 2026-11-03

**Question:** Does configured-process Save completion enqueue the same

[bridge completion branch](../../../cpp/src/internal/federation/process_federation_callback_bridge.cpp#L881)).

`HLAfederateState` conditional update. This differs from the embedded success
branch, which queues the update after `federationSaved()`, while the embedded

([embedded branch](../../../cpp/src/internal/runtime/umbra_rti_ambassador_save_restore_notifications.cpp#L168)).

([process case](../../../cpp/tests/ieee1516_2025_connection_process_federation_save_not_complete_catch2.cpp#L554)).
The public `3 → 1` success reflection remains embedded-test evidence only
([embedded case](../../../cpp/tests/joined_federate_mom_federate_state_save_restore_catch2.cpp#L139)).

## 2025 source resignation during queued regional TSO interaction — 2026-11-03

**Question:** When a publisher resigns after an explicit-source regional
timestamped interaction is accepted but before callback delivery, which Region
and retraction state survives, and what does the receiver observe?

**Evidence:** The embedded `HLA_EVOKED` test queues the constrained receiver's
advance, resigns the publisher, then advances an independent regulator. The
receiver observes the timestamped interaction before its grant with producer
identity, a conveyed Region set, and a supplied retraction handle. A later
publisher `Retract` call throws `FederateNotExecutionMember`
([focused test](../../../cpp/tests/timed_live_tso_regional_interaction_source_resignation_catch2.cpp#L15)).
Source shows resignation erasing publisher-owned Regions and terminalizing the
producer's retraction record, while the callback reconstructs receiver-side
Region designators from the accepted message's committed snapshot
([Region and retraction cleanup](../../../cpp/src/internal/federation/federation_registry_resign_lifecycle.cpp#L765),
[callback-scoped copies](../../../cpp/src/internal/runtime/callback_region_designator_copies.hpp#L16)).
The test's `retractionValid` report records only `MessageRetractionHandle::isValid()`;
it does not indicate that the departed producer can still call `Retract`.

The configured-process send path stores planned Region snapshots, the Resign
handler delegates to the registry, and TSO delivery retains receiver-side
callback Region copies through delivery acknowledgement. Reviewed process
regional TSO tests resign during teardown rather than while the source
interaction is pending, so this combined process outcome remains source-derived.
This was cross-linked with the existing Save/Restore case, where restoring an
earlier image revives its saved live retraction record.

[Save/Restore guide](../HLA-2025-FEDERATION-SAVE-RESTORE-FLOW-GUIDE.md). No
