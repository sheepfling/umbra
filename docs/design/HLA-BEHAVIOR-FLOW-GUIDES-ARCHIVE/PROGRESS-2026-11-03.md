## 2025 process TSO acknowledgment after pre-callback Retract — 2026-11-03

The client handles a retraction control event based on where the original
event resides. A still-pending interaction/removal event is erased from the
client queue and its delivery acknowledgment is deferred; if it has reached the
callback bridge, the per-message state suppresses a not-yet-started callback or
allows `requestRetraction` after callback start. Attribute events remain in the
queue and are handled by their callback-bridge retraction state. Suppressed
tracked delivery and ordinary callback completion both reach the private TSO
acknowledgment path, which defers nested requests until the current exchange
releases.

The focused process interaction test observes three pull-mode phases: Retract
before poll, after pull but before callback start, and after callback entry. In
the second phase it asserts the private acknowledgment eventually arrives, but
the fixture intentionally accepts two API fences before or after it. The
after-entry phase observes the public interaction and one `requestRetraction`;
the fixture waits for the acknowledgment and callback-start fence before
issuing Retract. The pushReceiveOrderEvents-enabled Resign case verifies no
attribute or removal callback after rejoin but makes no TSO-ack assertion. The
existing TSO client-boundary chart already explains the event-queue/bridge
branch, so no duplicate diagram was needed. Updated its process test evidence
and left the generic pull/push order unclaimed. No tests, builds, CI,
Requirements Lab, or 2010 content changed.

## 2025 process TSO acknowledgment transport deferral — 2026-11-03
